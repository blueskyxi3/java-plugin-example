02 · Process：由 master 托管

Process 插件是独立可执行服务，通过 HTTP 接口工作。宿主将 ZIP 解压到版本发布目录，分配本机端口，生成配置并启动子进程。

宿主负责插件负责
按当前 OS/ARCH 选择 ZIP，校验清单；生成 config.yaml、随机端口与 32 字节随机密钥。打开业务数据库、迁移自己的表，监听 HTTP，提供 /internal/manifest、业务 API 和资源。
exec.Command(..., -config ...)；注入 <PREFIX>HOST_SECRET 和回调地址。禁用/到期/卸载时排空请求并停止托管进程。组织插件仅操作 org_*，反馈插件管理其自身业务表；宿主用户和用量通过接口读取。
配置共享或独立数据库；对象存储经宿主桥接落到宿主侧 local/S3。共享数据库是物理连接共享；插件业务数据权限仍由自己的表与接口边界约束。

03 / SOURCE VERIFIED

03 · External：先部署，再配对接入

“安装”只把已部署且可访问的服务接入 AI Hub。宿主不分配远端端口、不写远端数据库配置，也不启动或停止远端容器。

服务地址使用安装输入的 url，为空时取数据库目录的 external_url；通信密钥来自目录的 secret_env 或 secret。宿主先验证 origin、凭据和远端清单一致性，随后执行初始化并登记。停用或授权到期会关闭宿主入口，但外部服务的进程仍由外部部署系统管理。

插件 → 宿主需要可达的 host_url。跨容器时 127.0.0.1 指向各自容器，不能套用 Process 的本机回调地址。外部服务的数据库由其部署配置决定，安装输入中的数据库选项不会替它改写 DSN。

部署模式与执行平面当前代码规则
master / control可托管 Process；External 仍需有匹配该节点的扩展点。
slave / data禁止 Process。External 也要通过扩展点匹配；当前注册的 6 个扩展点全属于 control，因此 organization / feedback 在 data 节点不执行。
判定依据Point.Plane 与 NodePlane() 匹配；当前 Manifest 没有独立 plane 字段。

04 · 安装、试用、购买：同一条提交链路

生命周期操作由 Runtime 的 operations 锁串行执行。初始化期间插件可以读取获准的服务目录，但浏览器请求被阻挡；保存登记与授权成功后才开放访问。

阶段ProcessExternal
PREPARE校验存储与数据库，选择并解压 ZIP，分配端口、生成密钥及配置。校验存储，读取目录配对密钥；验证外部地址、凭据和清单。
START / CHECK启动子进程，循环请求 /internal/manifest，最多等待 10 秒。不启动进程，验证已有 HTTP 服务的 /internal/manifest。
BOOTSTRAP/internal/bootstrap；组织插件显式读取用户目录，建立员工和首位模块管理员。使用相同内部协议初始化；目录读取需批准 users.directory.read。
PERSIST落盘安装记录和最终授权后清除 initializing。相同；记录模式、URL、回调地址、能力和授权。
失败处理恢复之前的安装/授权；新安装失败移除临时登记。已写插件业务数据不属于宿主的跨服务事务。恢复宿主登记/授权，不承诺撤销远端初始化副作用。

授权种类包括 trial、purchased 与手工登记兼容的 legacy；期限为 0 时永久有效。TrialUsed 随授权历史保留，卸载不会重新获得试用资格。install 路径复用有效授权，purchase 在这里完成授权转换，未串接支付订单扣款流程。

05 / SOURCE VERIFIED

05 · 如何知道是否安装、是否运行

安装判断看当前节点 Runtime 中是否存在登记；运行判断看 Enabled、Status、授权与初始化阶段。安装记录、有效授权和允许调用是三个独立条件。

接口 / 状态来源与含义
installed / not_installed市场调用 Runtime.Get(id)。当前节点没有可见登记时为未安装；有授权但已卸载仍可为未安装。
active启动/远端清单验证成功；实际请求还要通过 Acquire：节点匹配、启用、有效授权、未初始化且未修改运行配置。
disabled登记保留；手动停用标志保留，购买授权不会强制取消手动停用。
starting / upgrading启动验证中 / 升级正在排空请求并替换版本；新请求被阻挡。图中仅画稳定核心状态。
failed / incompatible进程退出或激活失败 / SDK 不兼容。Refresh() 还能检查清单及恢复健康状态，但当前未接入周期调度。
expired授权定时器到期：排空请求、停止托管进程、保留登记和数据，记录到期审计；请求入口也实时校验期限。
详情中的 pid / runtime_error点击已安装卡片请求 /:id/runtime。返回本机 PID，并按需探测插件 /internal/runtime；探测失败不会自动改写 active 状态。
“运行中”是宿主已知状态。

当前没有周期健康轮询。Process 退出由 cmd.Wait() 更新状态；External 离线可能先体现为代理 502 或运行详情错误。因此卡片 active 并非刚刚完成的一次端到端健康检测。

升级与卸载

升级先校验新版包/远端版本 → 阻挡新请求并排空旧请求 → 切换和激活 → 保存登记。保留原数据库、存储、密钥、配置和授权。只有目录明确声明 rollback_compatible 的 Process 才尝试启动旧程序；不回滚插件数据库迁移。External 升级要求先由外部部署方更新服务。卸载仅去掉宿主安装登记，保留授权、试用历史及安装目录数据。

06 · 用户交互：同源代理与两种身份

浏览器登录宿主，发现可用插件，动态 import 插件 JS，复用宿主 React/MUI/SDK。插件业务身份和返回宿主的委托身份各自验证。

GET /api/plugins 返回清单、当前用户扩展资料、api_base 和 asset_base。只有实现 user.identity.enrich 的插件调用内部 Profile；失败时该插件不加入本次发现结果。前端按“ID + 版本”缓存模块，只在用户变化或导航更新事件时刷新发现列表，没有周期发现轮询。

方向凭据与边界
浏览器 → 宿主宿主 Session 或 access token，重新核验用户状态及会话版本。仅允许代理 /assets/* 与 /api/v1/*；/internal/* 不向浏览器开放。
宿主 → 插件业务 API清除 Cookie、Authorization 与来路 X-AIHub-*；注入 X-AIHub-Identity，绑定用户、插件、方法、URI 与请求 ID，签名有效 30 秒。插件再检查员工、部门和模块管理员权限。
插件 → 宿主（用户委托）将 X-AIHub-Host-Authorization 作为 Bearer 使用，有效 1 分钟；宿主重新验证用户状态和 SessionVersion，再执行目标接口权限。不能访问插件管理、令牌、密钥等敏感接口。
插件 → 宿主（服务目录）Authorization: AIHubPlugin <id>:<secret>，仅开放安全用户目录投影，必须批准 users.directory.read；不继承某位用户的权限。
宿主 → 插件内部 APIX-AIHub-Plugin-Secret；用于 manifest、bootstrap、profile、事件、统计范围和运行配置。响应中的 X-AIHub-* 不透传给浏览器。

07 · 用户事件：提交后发布，锁内读取最新状态

Redis 连接只在宿主侧。插件从 HTTP 接收安全用户投影，不消费 Redis、不运行周期用户同步，也没有插件数据事件出箱。

频道      ai-hub:user-events
用户锁    ai-hub:user-events:lock:<user_id>
Redis 体  version=1, event_id, user_id, action, reason
HTTP      POST /internal/user-events
HTTP 体   Redis 事件字段 + user（锁内读取的安全投影）
条件实际行为
发布时机创建、资料/头像/角色/状态修改、删除事务成功后发布。额度和请求计数变化不发布；失败回滚不发布。
多宿主订阅每个实例都可收到同一事件；SETNX 用户锁有效 30 秒。拿锁后重读用户数据库并发出 HTTP；不是 exactly-once 去重。
插件应用组织插件校验事件后在 SyncMu 下更新员工投影。用户删除被标记为停用/宿主已删除，组织侧岗位与部门资料保留。
恢复Pub/Sub 没有持久化、离线重放或自动出箱重试；失败记录日志，通过显式“校准员工目录”读取分页用户目录修复。

频道已经不含版本号，事件 JSON 中的协议字段 version=1 仍用于校验。Redis 专用于同一 AI Hub 部署。切换频道时暂停用户资料变更、统一重启所有宿主副本，最后校准员工目录。

08 · 统计：插件决定可见成员，宿主计算真实用量

组织插件不复制调用记录或计费快照。浏览器只选择部门或员工，成员 ID 集合由插件授权计算，宿主不会相信浏览器自报的成员列表。

插件先调用自身 StatisticsAccess，再以用户委托访问 GET /api/plugin-data/organization/statistics。宿主验证委托与查询参数，服务认证调用 POST /internal/statistics/scope 再次核定范围，仅使用返回的成员 ID 查询宿主 statistics，按用户、日期和模型聚合。

该专用统计接口以插件的组织权限为授权依据，不要求用户拥有宿主分析页面权限；其它普通宿主接口仍执行各自权限。金额按十进制字符串传输并携带宿主币种。路径名保留 /plugin-data/...，但它是实时查询接口，与已删除的三张插件数据表无关。

09 · 存储：共享能力，固定插件目录边界

存储写入由宿主执行。即使选择插件独立存储，local 路径和 S3 驱动仍由宿主使用，不能把它理解为插件所在机器的文件路径。

插件先执行员工/管理员等业务权限，再携带用户委托访问宿主存储接口。宿主验证插件处于可用状态、声明 storage.objects 并设置有效的 storage_directory；路径前缀由安装清单固定，插件不能任意选择其他插件的目录。

组织图片  plugins/organization/logos/YYYYMMDD/<sha256>.<ext>
反馈图片  plugins/feedback/images/YYYYMMDD/<sha256>.<ext>

上传对象限制 5 MiB，日期与内容哈希组成对象键；目录读取只接受规定格式。宿主根据 Deployment.Storage.Shared 选择共用驱动或独立驱动，数据库与存储的 shared 选项互不绑定。

10 · 地址修改：两个方向一起校验

插件 URL 是“宿主 → 插件”；Host URL 是“插件 → 宿主”。点击已安装卡片可以查看它们；只有 Root 且具备插件管理权限可以修改。

先验证两个 origin、目标插件清单及运行配置接口，验证阶段不改变远端回调。随后设置 configuring 阻挡新请求并排空旧请求，更新远端 host_url，切换宿主登记的 URL/HostURL 并持久化。失败会恢复宿主记录并尝试恢复远端旧回调，回滚失败会明确返回错误。

已保存的回调地址通过服务认证内部请求的 X-AIHub-Host-Base-URL 传递，插件副本可收敛到相同回调配置。此操作不替代外部服务部署或端口映射管理。
